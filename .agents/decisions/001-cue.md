## Decision

- **Cue** is a browser app, not a desktop app: live captions, screen context and an AI that answers during a call. TypeScript + Vite + React; one small Node server (`server/index.ts`, no framework) that also serves the built app.
- **Akamai Cloud Inference** answers (`/api/ask`, streamed), writes recaps (`/api/recap`) and, if a speech model is set, captions the other side of a call (`/api/transcribe`). Called through the OpenAI-compatible API; endpoint, key and model come from env vars.
- **Akamai Object Storage** holds every saved recap (`recaps/<uuid>.json`, private bucket, read through the server). The share link `/r/<uuid>` depends on it: this is the "other Akamai service" feature.
- **Compute (a Linode)** hosts the server behind HTTPS (mic and screen capture only work on HTTPS or localhost).
- **Output check** (`checkAnswer` in `shared/cue.ts`): the model must quote exact words when it uses the transcript; Cue checks every quote against what was really said and shows ✓ / ⚠ / ○ on each answer and each recap action item.
- Mic captions use the browser's Web Speech API (free, instant). The other side's audio comes from a shared tab, sent in 7-second chunks to the speech model.
- The pop-out window uses Document Picture-in-Picture so answers stay on top of other apps. Cue does **not** try to hide from screen sharing or proctoring.

## Why

- A browser app needs no install, so judges can try it from a link.
- The quote check is cheap, instant, explainable and catches the worst failure (making up what someone said).
- Object Storage makes recaps shareable without a database.

## Options we didn't pick

- An Electron overlay invisible to screen share: that's built for cheating in interviews and exams. Not doing it.
- Streaming audio over WebSockets: chunked uploads are simpler and good enough for captions.
